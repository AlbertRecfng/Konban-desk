# Kanban

Веб-приложение для управления задачами в стиле Kanban: доски, колонки, карточки задач с перетаскиванием, совместная работа с ролями, WIP-лимиты и обновление доски в реальном времени.

Курсовая работа.

## Возможности

- **Регистрация и вход.** Пароли хранятся в виде bcrypt-хеша. Сессия держится на коротком JWT access-токене и refresh-токене в httpOnly-cookie, который меняется при каждом обновлении.
- **Доски.** Создание, переименование, удаление. Новая доска сразу получает колонки «К выполнению», «В работе», «Готово».
- **Колонки.** Добавление, переименование, удаление, перетаскивание.
- **Задачи.** Название, описание, приоритет, срок, исполнитель. Перетаскивание внутри колонки и между колонками. Просроченные задачи подсвечиваются.
- **WIP-лимит колонки.** Максимальное число задач в колонке. В заполненную колонку нельзя добавить или перенести задачу; лимит проверяет и сервер.
- **Совместная работа.** Владелец приглашает участников по email с ролью «Редактор» или «Только просмотр».
- **Обновления в реальном времени.** Изменения других участников появляются на доске сразу, без перезагрузки страницы.
- **Поиск и фильтры** по названию, приоритету, исполнителю и просроченным задачам.

## Установка и запуск

Все команды выполняются из корня проекта.

1. Установить зависимости:
   ```bash
   npm install
   ```

2. Создать файл настроек `server/.env` по образцу `server/.env.example`:
   ```bash
   cp server/.env.example server/.env
   ```
   В Windows (PowerShell): `copy server\.env.example server\.env`.

   В `DATABASE_URL` указать пароль пользователя PostgreSQL, в `JWT_ACCESS_SECRET` - любую длинную случайную строку.

3. Создать базу данных, применить миграции и загрузить демо-данные:
   ```bash
   npm run db:create
   npm run db:migrate
   npm run db:seed
   ```

4. Запустить сервер и клиент:
   ```bash
   npm run dev
   ```
   Приложение откроется по адресу http://localhost:5173, API работает на http://localhost:4000/api.

### Демо-аккаунты

## Production-запуск и доступ из интернета

В production один сервер на порту 4000 отдаёт и сайт, и API, и Socket.IO:

```bash
npm run build
npm start
```

Приложение откроется по адресу http://localhost:4000.

Чтобы открыть его с другого компьютера через интернет, можно использовать Cloudflare Tunnel. Не нужны ни «белый» IP, ни настройка роутера, а HTTPS включается сразу.

1. Установить cloudflared (один раз). В Windows:
   ```powershell
   winget install --id Cloudflare.cloudflared
   ```
2. При запущенном `npm start` в отдельном терминале выполнить:
   ```bash
   npm run tunnel
   ```
3. В выводе появится адрес вида `https://<случайные-слова>.trycloudflare.com`. По нему приложение доступно из любого браузера.

Адрес меняется при каждом запуске туннеля. Пока туннель работает, приложение доступно всем, у кого есть ссылка; после показа его стоит остановить (Ctrl+C).

## База данных

| Таблица | Содержимое |
|---|---|
| `users` | пользователи (email, имя, хеш пароля) |
| `refresh_tokens` | активные сессии (хранится SHA-256 хеш токена) |
| `boards` | доски |
| `board_members` | участники досок и их роли (`owner`, `editor`, `viewer`) |
| `board_columns` | колонки: порядок (`position`) и WIP-лимит (`wip_limit`) |
| `tasks` | задачи: колонка, порядок, приоритет, срок, исполнитель |

Порядок колонок и задач хранится в поле `position` (0, 1, 2…). Перенос выполняется в транзакции с блокировкой затронутых колонок (`SELECT … FOR UPDATE`), поэтому одновременные изменения от разных пользователей не нарушают порядок и не превышают WIP-лимит.

## API

Все маршруты, кроме `/api/auth/*`, требуют заголовок `Authorization: Bearer <accessToken>`. Ошибки возвращаются в формате `{ "error": "сообщение" }`.

| Метод | Путь | Назначение |
|---|---|---|
| POST | `/api/auth/register` | регистрация |
| POST | `/api/auth/login` | вход |
| POST | `/api/auth/refresh` | новый access-токен по refresh-cookie |
| POST | `/api/auth/logout` | выход |
| GET | `/api/auth/me` | текущий пользователь |
| GET, POST | `/api/boards` | список досок, создание доски |
| GET, PATCH, DELETE | `/api/boards/:id` | доска целиком (участники, колонки, задачи), изменение, удаление |
| POST | `/api/boards/:id/columns` | новая колонка |
| GET, POST | `/api/boards/:id/members` | участники, приглашение по email |
| PATCH, DELETE | `/api/boards/:id/members/:userId` | смена роли, удаление участника |
| PATCH, DELETE | `/api/columns/:id` | изменение (название, WIP-лимит), удаление колонки |
| PATCH | `/api/columns/:id/move` | перенос колонки на позицию |
| POST | `/api/columns/:id/tasks` | новая задача |
| GET, PATCH, DELETE | `/api/tasks/:id` | задача: просмотр, изменение, удаление |
| PATCH | `/api/tasks/:id/move` | перенос задачи в колонку на позицию |

Права проверяются по роли на доске: просмотр - `viewer`, изменение колонок и задач - `editor`, управление доской и участниками - `owner`. Чужая доска отвечает 404, чтобы не раскрывать её существование.

Обновления в реальном времени: клиент подключается к Socket.IO по пути `/api/socket.io` с access-токеном. После изменения доски сервер отправляет её участникам событие `board:changed` с id доски, и клиент заново загружает её через API.
